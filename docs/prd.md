# Документ требований

## 1. Обзор приложения

### 1.1 Название приложения
Система учёта продаж и финансов

### 1.2 Описание
Веб-приложение для комплексного учёта продаж, финансовых операций и планирования компании, заменяющее ручной учёт в Excel (/workspace/app-dglnmr1k1czl/tasks/123.xlsx). Система обеспечивает учёт сделок по сотрудникам, автоматический расчёт предоплат и остатков, контроль выполнения планов продаж, учёт расходов и поступлений по каналам оплаты, формирование сводных балансов и отчётов. Поддерживает динамическое управление списком сотрудников, гибкую настройку планов продаж, систему авторизации с разграничением прав доступа и подтверждением сделок.

## 2. Пользователи и сценарии использования

### 2.1 Целевые пользователи
  - Директор/Администратор: полный доступ ко всем функциям, подтверждение сделок, управление правами доступа
  - Сотрудники компании (менеджеры по продажам, лидорубы, технологи, установщики, маркетологи, бренд-менеджеры, бухгалтеры, управляющие): ограниченный доступ, внесение продаж, просмотр собственных данных

### 2.2 Основные сценарии использования
  - Авторизация в системе с разграничением прав доступа
  - Управление списком сотрудников (добавление, переименование, удаление, назначение должности, установка зарплаты)
  - Регистрация сделок сотрудниками с автоматическим расчётом предоплаты и остатков
  - Подтверждение сделок директором/администратором
  - Установка и изменение планов продаж для компании и каждого сотрудника вручную
  - Фильтрация данных по должности и конкретному сотруднику
  - Отслеживание выполнения планов продаж по сотрудникам
  - Учёт расходов и поступлений денежных средств по каналам
  - Просмотр балансов наличных и счетов
  - Формирование отчётов по месяцам и сотрудникам
  - Управление правами доступа сотрудников ко всем разделам приложения
  - Ввод и анализ данных о новых клиентах и эффективности маркетинга

### 3.2 Страница авторизации

#### 3.2.1 Вход в систему
  - Пользователь вводит логин и пароль
  - Система проверяет учётные данные
  - При успешной авторизации система определяет роль пользователя (директор/администратор или сотрудник) и предоставляет соответствующий доступ
  - При неудачной авторизации система показывает сообщение об ошибке

#### 3.2.2 Восстановление пароля
  - Пользователь запрашивает восстановление пароля
  - Система отправляет инструкции по восстановлению

### 3.3 Страница управления сотрудниками

Доступ: только директор/администратор

#### 3.3.1 Список сотрудников
  - Отображать список всех сотрудников
  - Для каждого сотрудника показывать: имя, должность, зарплату, права доступа, действия (редактировать, удалить)

#### 3.3.2 Добавление сотрудника
  - Пользователь нажимает кнопку «Добавить сотрудника»
  - Пользователь вводит: имя, должность (выбор из списка: Менеджер по продажам, Лидоруб, Технолог, Установщик, Маркетолог, Бренд-менеджер, Бухгалтер, Управляющий), зарплату, логин, пароль
  - Пользователь настраивает права доступа
  - Система сохраняет сотрудника в хранилище данных
  - Новый сотрудник появляется во всех разделах приложения

#### 3.3.3 Переименование сотрудника
  - Пользователь выбирает сотрудника и нажимает «Редактировать»
  - Пользователь вводит новое имя
  - Система обновляет имя сотрудника во всех связанных данных

#### 3.3.4 Назначение должности
  - Пользователь выбирает сотрудника и изменяет должность
  - Система обновляет должность сотрудника

#### 3.3.5 Установка зарплаты
  - Пользователь вводит размер зарплаты для сотрудника
  - Для менеджеров по продажам зарплата рассчитывается от их личных продаж
  - Для всех остальных должностей зарплата рассчитывается от общей выручки компании
  - Система сохраняет настройки зарплаты

#### 3.3.6 Управление правами доступа
  - Пользователь настраивает права доступа для каждого сотрудника
  - Директор/администратор имеет полный доступ ко всем функциям
  - Сотрудник может вносить продажи, видит только свои данные, имеет ограниченный доступ

#### 3.3.7 Удаление сотрудника
  - Пользователь выбирает сотрудника и нажимает «Удалить»
  - Система показывает предупреждение: «Удаление сотрудника приведёт к удалению всех его сделок, поступлений и планов. Продолжить?»
  - Пользователь подтверждает удаление
  - Система удаляет сотрудника и все связанные данные из хранилища

### 3.4 Страница продаж текущего месяца

#### 3.4.1 Фильтр по должности
  - Пользователь выбирает должность из списка
  - Система отображает только сотрудников выбранной должности
  - По умолчанию на странице Продажи отображаются только менеджеры по продажам

#### 3.4.2 Фильтр по сотруднику
  - Пользователь выбирает конкретного сотрудника из списка
  - Система отображает данные только выбранного сотрудника

#### 3.4.3 Выбор месяца
  - Пользователь выбирает месяц из списка (Июнь, Июль, Август и далее)
  - Система отображает данные выбранного месяца

#### 3.4.4 Раздел сотрудника

Для каждого менеджера по продажам отображается:

##### 3.4.4.1 Таблица сделок
  - Отображать список всех сделок сотрудника за выбранный месяц
  - Для каждой сделки показывать поля: дата, номер телефона/адрес клиента, адрес, ФИО, способ оплаты, модель дверей, общая сумма (для бонуса), оплачено, дата предоплаты, сумма до 70% предоплаты, сумма предоплаты 70%, остатки по заказу, статус подтверждения
  - Сотрудник может добавить новую сделку
  - Сотрудник вводит: дату, номер телефона/адрес клиента, адрес, ФИО, способ оплаты (выбор из списка: Kaspi Bank, Halyk Bank, Freedom Bank, наличные, Kaspi Bank и нал, другие), модель дверей, общую сумму, оплачено, дату предоплаты
  - Система автоматически рассчитывает: сумму предоплаты 70% = общая сумма × 0.7, остатки по заказу = общая сумма − оплачено
  - Система сохраняет сделку в хранилище данных со статусом «Ожидает подтверждения»
  - Сотрудник может редактировать только свои неподтверждённые сделки
  - Директор/администратор может редактировать любые сделки
  - Сотрудник может удалить только свои неподтверждённые сделки
  - Директор/администратор может удалить любые сделки
  - При изменении или удалении сделки система пересчитывает все итоги и балансы

##### 3.4.4.2 Итоги по сотруднику
  - Система автоматически рассчитывает и отображает:
    - Общая выручка = сумма всех «общая сумма» подтверждённых сделок сотрудника
    - Общее оплачено = сумма всех «оплачено» подтверждённых сделок сотрудника
    - Сумма 70% предоплаты = сумма всех «сумма предоплаты 70%» подтверждённых сделок сотрудника
    - Остатки по заказам = сумма всех «остатки по заказу» подтверждённых сделок сотрудника

#### 3.4.5 План продаж на месяц
  - Отображать план продаж компании на выбранный месяц
  - Директор/администратор вручную вводит план продаж компании на месяц
  - Директор/администратор вручную устанавливает индивидуальный план продаж для каждого сотрудника на выбранный месяц
  - Система сохраняет планы продаж в хранилище данных
  - Система рассчитывает и отображает для каждого сотрудника:
    - Прогресс плана = (общая выручка сотрудника / индивидуальный план продаж) × 100%
    - Недостающая сумма = индивидуальный план продаж − общая выручка сотрудника
    - Количество продаж = количество подтверждённых сделок сотрудника
    - Средний чек = общая выручка сотрудника / количество продаж
    - План на чистую прибыль (вводится директором/администратором)
    - План на дивиденды (вводится директором/администратором)
  - При изменении плана продаж система немедленно пересчитывает прогресс, недостающую сумму, план на чистую прибыль и дивиденды

### 3.5 Страница подтверждения сделок

Доступ: только директор/администратор

#### 3.5.1 Список неподтверждённых сделок
  - Отображать список всех сделок со статусом «Ожидает подтверждения»
  - Для каждой сделки показывать: сотрудника, дату, клиента, сумму, все детали сделки

#### 3.5.2 Подтверждение/отклонение сделки
  - Директор/администратор просматривает детали сделки
  - Директор/администратор подтверждает сделку — система изменяет статус на «Подтверждена» и включает сделку в расчёты итогов и балансов
  - Директор/администратор отклоняет сделку — система изменяет статус на «Отклонена» и исключает сделку из расчётов

### 3.6 Страница финансов и балансов

#### 3.6.1 Общие остатки
  - Отображать текущие балансы:
    - Остаток наличных
    - Остаток на счёте Kaspi Bank (с отображением логотипа банка)
    - Остаток на счёте Halyk Bank (с отображением логотипа банка)
    - Остаток на счёте Freedom Bank (с отображением логотипа банка)
  - Система рассчитывает балансы по формулам:
    - Остаток наличных = приход наличными − расход наличными
    - Остаток на счёте = поступления на счёт − расходы по счёту

#### 3.6.2 Расходы
  - Отображать список всех расходов
  - Пользователь может добавить расход
  - Пользователь вводит: дату, сумму, канал (по карте: Kaspi Bank/Halyk Bank/Freedom Bank или наличными), описание
  - Система сохраняет расход в хранилище данных
  - Пользователь может редактировать или удалить расход
  - При изменении расходов система пересчитывает балансы

#### 3.6.3 Поступления денег
  - Отображать список всех поступлений с детализацией: от кого, общая сумма, количество, сотрудник, комментарий, поступление денег (дата), счёт/касса (Kaspi Bank/Halyk Bank/Freedom Bank/наличные)
  - Пользователь может добавить поступление
  - Пользователь вводит: от кого, общую сумму, количество, сотрудника (выбор из списка сотрудников), комментарий, дату поступления, счёт/кассу
  - Система сохраняет поступление в хранилище данных
  - Пользователь может редактировать или удалить поступление
  - При изменении поступлений система пересчитывает балансы

### 3.7 Страница прав доступа

Доступ: только директор/администратор

#### 3.7.1 Список сотрудников
  - Отображать список всех сотрудников
  - Для каждого сотрудника показывать имя, должность, текущие права доступа к разделам

#### 3.7.2 Управление доступом к разделам
  - Администратор выбирает сотрудника
  - Система отображает список всех разделов приложения: dashboard, sales, salary, managers, expenses, income, transfers, permissions, profit, daily-report
  - Для каждого раздела администратор может включить или отключить доступ
  - Система сохраняет настройки прав доступа в хранилище данных
  - При попытке сотрудника открыть раздел без доступа система показывает сообщение «Доступ запрещён»

### 3.8 Страница чистой прибыли

#### 3.8.1 Список строк расчёта
  - Отображать список всех строк расчёта чистой прибыли
  - Для каждой строки показывать: название, тип (formula/value/percentage_of_revenue), значение/формулу/процент, рассчитанное значение

#### 3.8.2 Добавление строки
  - Пользователь нажимает кнопку «Добавить строку»
  - Пользователь выбирает тип строки:
    - formula: строка с формулой расчёта
    - value: строка с фиксированным значением
    - percentage_of_revenue: строка с процентом от общей выручки
  - Для типа formula пользователь вводит название и формулу
  - Для типа value пользователь вводит название и значение
  - Для типа percentage_of_revenue пользователь вводит название (например «Логистика», «Маркетинг») и процент (например 10)
  - Система сохраняет строку в хранилище данных
  - Пользователь может добавить неограниченное количество строк типа percentage_of_revenue
  - Пользователь может редактировать процент в любой момент
  - При изменении процента система немедленно пересчитывает значение строки

#### 3.8.3 Итоговый расчёт
  - Система автоматически рассчитывает значения всех строк:
    - Для типа formula: выполняет расчёт по формуле
    - Для типа value: использует введённое значение
    - Для типа percentage_of_revenue: рассчитывает значение = процент × общая выручка / 100
  - Система отображает итоговую чистую прибыль

### 3.9 Страница ежедневного отчёта

Доступ: только сотрудники с правом доступа к разделу daily-report

#### 3.9.1 Форма добавления записи
  - Пользователь нажимает кнопку «Добавить запись»
  - Пользователь вводит:
    - Дата
    - Источник клиента (канал маркетинга)
    - Количество новых клиентов
    - Количество заявок
    - Количество закрытых сделок
    - Сумма продаж
    - Стоимость рекламы/маркетинга
    - Комментарий
  - Система сохраняет запись в хранилище данных

#### 3.9.2 Таблица записей
  - Отображать список всех записей
  - Для каждой записи показывать: дату, источник клиента, количество новых клиентов, количество заявок, количество закрытых сделок, сумму продаж, стоимость рекламы/маркетинга, комментарий
  - Пользователь может фильтровать записи по дате
  - Пользователь может фильтровать записи по каналу маркетинга
  - Пользователь может редактировать или удалить запись

#### 3.9.3 Аналитический блок
  - Система автоматически рассчитывает и отображает:
    - Конверсия (заявки → сделки) = (количество закрытых сделок / количество заявок) × 100%
    - Стоимость привлечения клиента (CAC) = стоимость рекламы/маркетинга / количество новых клиентов
    - ROI маркетинга = ((сумма продаж − стоимость рекламы/маркетинга) / стоимость рекламы/маркетинга) × 100%
  - Показатели рассчитываются для выбранного периода или канала

### 3.10 Страница отчётов

#### 3.10.1 Распределение выручки по способам оплаты
  - Система рассчитывает и отображает для выбранного месяца:
    - Сумма по способу оплаты Kaspi Bank = сумма всех «оплачено» подтверждённых сделок со способом оплаты «Kaspi Bank»
    - Сумма по способу оплаты Halyk Bank = сумма всех «оплачено» подтверждённых сделок со способом оплаты «Halyk Bank»
    - Сумма по способу оплаты Freedom Bank = сумма всех «оплачено» подтверждённых сделок со способом оплаты «Freedom Bank»
    - Сумма по способу оплаты наличные = сумма всех «оплачено» подтверждённых сделок со способом оплаты «наличные»
    - Сумма по способу оплаты Kaspi Bank и нал = сумма всех «оплачено» подтверждённых сделок со способом оплаты «Kaspi Bank и нал»
    - Другие способы оплаты

#### 3.10.2 Сводные показатели по месяцам
  - Пользователь выбирает период (один или несколько месяцев)
  - Система отображает для выбранного периода:
    - Общая выручка по всем сотрудникам
    - Общее оплачено по всем сотрудникам
    - Общие расходы
    - Общие поступления
    - Итоговый баланс

## 4. Бизнес-правила и логика

### 4.1 Система авторизации и прав доступа
  - Система поддерживает две роли пользователей: директор/администратор и сотрудник
  - Директор/администратор имеет полный доступ ко всем функциям системы
  - Сотрудник может вносить продажи, видит только свои данные, имеет ограниченный доступ к функциям
  - Директор/администратор может управлять правами доступа для каждого сотрудника ко всем разделам приложения (dashboard, sales, salary, managers, expenses, income, transfers, permissions, profit, daily-report)
  - Все действия пользователей сохраняются в хранилище данных

### 4.2 Управление сотрудниками
  - Список сотрудников хранится в хранилище данных
  - При добавлении сотрудника система создаёт новую запись в справочнике сотрудников с указанием должности, зарплаты, логина, пароля и прав доступа
  - При переименовании сотрудника система обновляет имя во всех связанных данных (сделки, поступления, планы продаж)
  - При удалении сотрудника система удаляет все его сделки, поступления и планы продаж
  - Список сотрудников используется во всех частях приложения: таблицы продаж, поступления, отчёты
  - Система поддерживает следующие должности: Менеджер по продажам, Лидоруб, Технолог, Установщик, Маркетолог, Бренд-менеджер, Бухгалтер, Управляющий

### 4.3 Расчёт зарплаты
  - Для менеджеров по продажам зарплата рассчитывается от их личных продаж
  - Для всех остальных должностей (Лидоруб, Технолог, Установщик, Маркетолог, Бренд-менеджер, Бухгалтер, Управляющий) зарплата рассчитывается от общей выручки компании
  - Директор/администратор устанавливает размер зарплаты для каждого сотрудника

### 4.4 Фильтрация данных
  - На странице Продажи по умолчанию отображаются только менеджеры по продажам
  - Пользователь может применить фильтр по должности для отображения сотрудников других должностей
  - Пользователь может применить фильтр по конкретному сотруднику для отображения данных только этого сотрудника
  - Фильтры сохраняются в сессии пользователя

### 4.5 Управление планом продаж
  - План продаж компании на месяц вводится директором/администратором вручную
  - Индивидуальный план продаж для каждого сотрудника на месяц устанавливается директором/администратором вручную
  - План продаж хранится для каждого сотрудника и каждого месяца отдельно
  - При изменении плана продаж система немедленно пересчитывает:
    - Прогресс плана = (общая выручка сотрудника / индивидуальный план продаж) × 100%
    - Недостающая сумма = индивидуальный план продаж − общая выручка сотрудника
    - План на чистую прибыль
    - План на дивиденды

### 4.6 Подтверждение сделок
  - Все сделки, внесённые сотрудниками, сохраняются со статусом «Ожидает подтверждения»
  - Директор/администратор просматривает неподтверждённые сделки и подтверждает или отклоняет их
  - Только подтверждённые сделки включаются в расчёты итогов, балансов и отчётов
  - Сотрудник может редактировать или удалять только свои неподтверждённые сделки
  - Директор/администратор может редактировать или удалять любые сделки

### 4.7 Автоматический расчёт предоплаты и остатков
  - При добавлении или редактировании сделки:
    - Сумма предоплаты 70% = общая сумма × 0.7
    - Остатки по заказу = общая сумма − оплачено

### 4.8 Расчёт итогов по сотруднику
  - Общая выручка = сумма всех «общая сумма» подтверждённых сделок сотрудника за месяц
  - Общее оплачено = сумма всех «оплачено» подтверждённых сделок сотрудника за месяц
  - Сумма 70% предоплаты = сумма всех «сумма предоплаты 70%» подтверждённых сделок сотрудника за месяц
  - Остатки по заказам = сумма всех «остатки по заказу» подтверждённых сделок сотрудника за месяц

### 4.9 Расчёт прогресса плана продаж
  - Прогресс плана = (общая выручка сотрудника / индивидуальный план продаж сотрудника) × 100%
  - Недостающая сумма = индивидуальный план продаж сотрудника − общая выручка сотрудника
  - Количество продаж = количество подтверждённых сделок сотрудника за месяц
  - Средний чек = общая выручка сотрудника / количество продаж

### 4.10 Расчёт балансов
  - Остаток наличных = сумма всех поступлений наличными − сумма всех расходов наличными
  - Остаток на счёте Kaspi Bank = сумма всех поступлений на Kaspi Bank − сумма всех расходов по Kaspi Bank
  - Остаток на счёте Halyk Bank = сумма всех поступлений на Halyk Bank − сумма всех расходов по Halyk Bank
  - Остаток на счёте Freedom Bank = сумма всех поступлений на Freedom Bank − сумма всех расходов по Freedom Bank

### 4.11 Распределение выручки по способам оплаты
  - Для каждого способа оплаты (Kaspi Bank, Halyk Bank, Freedom Bank, наличные, Kaspi Bank и нал, другие) система суммирует все «оплачено» подтверждённых сделок с соответствующим способом оплаты за выбранный месяц

### 4.12 Управление правами доступа к разделам
  - Администратор может включать или отключать доступ сотрудника к каждому разделу приложения: dashboard, sales, salary, managers, expenses, income, transfers, permissions, profit, daily-report
  - Настройки прав доступа сохраняются в хранилище данных
  - При попытке доступа к разделу система проверяет права пользователя
  - Если доступ запрещён, система показывает сообщение «Доступ запрещён»

### 4.13 Расчёт чистой прибыли
  - Система поддерживает три типа строк расчёта:
    - formula: значение рассчитывается по формуле
    - value: используется фиксированное значение
    - percentage_of_revenue: значение рассчитывается как процент от общей выручки
  - Для строк типа percentage_of_revenue:
    - Значение = процент × общая выручка / 100
    - При изменении процента система немедленно пересчитывает значение
    - При изменении общей выручки система автоматически пересчитывает значения всех строк типа percentage_of_revenue

### 4.14 Аналитика ежедневного отчёта
  - Конверсия (заявки → сделки) = (количество закрытых сделок / количество заявок) × 100%
  - Стоимость привлечения клиента (CAC) = стоимость рекламы/маркетинга / количество новых клиентов
  - ROI маркетинга = ((сумма продаж − стоимость рекламы/маркетинга) / стоимость рекламы/маркетинга) × 100%
  - Показатели рассчитываются для выбранного периода или канала маркетинга

### 4.15 Хранение данных
  - Все сделки, расходы, поступления, планы продаж, список сотрудников, учётные данные пользователей, права доступа, строки расчёта чистой прибыли, записи ежедневного отчёта сохраняются в хранилище данных
  - Данные организованы по месяцам и сотрудникам
  - При изменении или удалении операций все связанные итоги и балансы автоматически пересчитываются

### 4.16 Валидация данных
  - Имя сотрудника не может быть пустым
  - Логин и пароль не могут быть пустыми
  - Общая сумма сделки должна быть положительным числом
  - Оплачено не может превышать общую сумму
  - Дата сделки, расхода, поступления не может быть в будущем
  - Способ оплаты должен быть выбран из предопределённого списка
  - План продаж должен быть положительным числом
  - Сумма расхода и поступления должна быть положительным числом
  - Должность должна быть выбрана из предопределённого списка
  - Зарплата должна быть положительным числом
  - Процент для строки типа percentage_of_revenue должен быть положительным числом
  - Количество новых клиентов, заявок, закрытых сделок должно быть неотрицательным целым числом
  - Сумма продаж и стоимость рекламы/маркетинга должны быть положительными числами

## 5. Исключительные ситуации и граничные случаи

| Ситуация | Поведение системы |
|----------|-------------------|
| Пользователь вводит неверный логин или пароль | Система отклоняет вход и показывает сообщение об ошибке |
| Сотрудник пытается получить доступ к чужим данным | Система отклоняет запрос и показывает сообщение «Доступ запрещён» |
| Сотрудник пытается редактировать подтверждённую сделку | Система отклоняет действие и показывает сообщение «Нельзя редактировать подтверждённую сделку» |
| Пользователь вводит пустое имя сотрудника | Система отклоняет ввод и показывает сообщение об ошибке |
| Пользователь удаляет сотрудника с существующими сделками | Система показывает предупреждение и запрашивает подтверждение |
| Пользователь вводит отрицательную сумму | Система отклоняет ввод и показывает сообщение об ошибке |
| Пользователь вводит «оплачено» больше «общей суммы» | Система отклоняет ввод и показывает сообщение об ошибке |
| Пользователь выбирает дату в будущем | Система отклоняет ввод и показывает сообщение об ошибке |
| Пользователь удаляет сделку/расход/поступление | Система запрашивает подтверждение перед удалением |
| У сотрудника нет сделок за месяц | Система показывает сообщение «Нет сделок» и итоги равны нулю |
| План продаж не установлен для сотрудника | Система показывает прогресс плана как 0% |
| Количество продаж равно нулю | Средний чек не рассчитывается или показывается как 0 |
| Нет расходов или поступлений | Балансы рассчитываются на основе имеющихся данных |
| Список сотрудников пуст | Система показывает сообщение «Нет сотрудников. Добавьте первого сотрудника» |
| Нет неподтверждённых сделок | Система показывает сообщение «Нет сделок, ожидающих подтверждения» |
| Сотрудник пытается открыть раздел без доступа | Система показывает сообщение «Доступ запрещён» |
| Пользователь вводит отрицательный процент для строки percentage_of_revenue | Система отклоняет ввод и показывает сообщение об ошибке |
| Общая выручка равна нулю | Значения строк типа percentage_of_revenue равны нулю |
| Количество заявок равно нулю | Конверсия не рассчитывается или показывается как 0% |
| Количество новых клиентов равно нулю | CAC не рассчитывается или показывается как 0 |
| Стоимость рекламы/маркетинга равна нулю | ROI не рассчитывается или показывается как 0% |
| Нет записей в ежедневном отчёте | Система показывает сообщение «Нет записей» и аналитические показатели равны нулю |

## 6. Критерии приёмки

1. Директор/администратор авторизуется в системе с полным доступом
2. Директор/администратор открывает страницу управления сотрудниками и добавляет нового сотрудника с именем «Айбар», должностью «Менеджер по продажам», зарплатой 500 000 тенге, логином и паролем
3. Директор/администратор открывает страницу прав доступа, выбирает сотрудника Айбар и включает доступ к разделам sales и daily-report, отключает доступ к разделу profit
4. Сотрудник Айбар авторизуется в системе с ограниченным доступом
5. Сотрудник Айбар открывает страницу продаж, выбирает текущий месяц (август 2026) и видит свой раздел
6. Сотрудник Айбар добавляет сделку с указанием даты 2026-08-03, клиента, адреса, ФИО, способа оплаты Kaspi Bank, модели дверей, общей суммы 1 000 000 тенге, оплачено 700 000 тенге
7. Система автоматически рассчитывает сумму предоплаты 70% = 700 000 тенге и остатки по заказу = 300 000 тенге, сохраняет сделку со статусом «Ожидает подтверждения»
8. Директор/администратор открывает страницу подтверждения сделок, видит сделку Айбара и подтверждает её
9. Система изменяет статус сделки на «Подтверждена» и включает её в расчёты итогов
10. Директор/администратор устанавливает план продаж компании на август 2026 = 50 000 000 тенге
11. Директор/администратор устанавливает индивидуальный план продаж для сотрудника Айбар на август 2026 = 10 000 000 тенге
12. Система отображает прогресс плана Айбара (10%), недостающую сумму (9 000 000 тенге), количество продаж (1), средний чек (1 000 000 тенге)
13. Директор/администратор открывает страницу чистой прибыли и добавляет строку типа percentage_of_revenue с названием «Логистика» и процентом 10
14. Система автоматически рассчитывает значение строки = 10% × 1 000 000 = 100 000 тенге
15. Директор/администратор изменяет процент строки «Логистика» на 15
16. Система немедленно пересчитывает значение строки = 15% × 1 000 000 = 150 000 тенге
17. Сотрудник Айбар открывает страницу ежедневного отчёта и добавляет запись с датой 2026-08-10, источником клиента «Instagram», количеством новых клиентов 5, количеством заявок 10, количеством закрытых сделок 3, суммой продаж 3 000 000 тенге, стоимостью рекламы 100 000 тенге
18. Система рассчитывает и отображает конверсию (30%), CAC (20 000 тенге), ROI маркетинга (2900%)
19. Сотрудник Айбар пытается открыть страницу чистой прибыли
20. Система показывает сообщение «Доступ запрещён»

## 7. Функции, не реализуемые в текущей версии

  - Мультивалютность
  - Синхронизация с банковскими счетами
  - Сканирование и распознавание чеков
  - Мобильное приложение
  - Экспорт данных в Excel
  - Повторяющиеся операции (автоматическое создание регулярных расходов)
  - Интеграции с внешними сервисами (CRM, бухгалтерские системы)
  - Уведомления и напоминания
  - Графики и диаграммы
  - Прогнозирование и аналитика на основе исторических данных
  - Управление складом и товарными остатками
  - Учёт возвратов и отмен заказов
  - Двухфакторная аутентификация
  - Журнал аудита действий пользователей
  - Массовое импортирование данных
  - Автоматическое распределение клиентов по каналам маркетинга
  - Сравнение эффективности каналов маркетинга за разные периоды
  - Прогнозирование ROI на основе исторических данных
